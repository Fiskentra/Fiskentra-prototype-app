# Возврат по треку и поиск мест — F6 / F7

Реализация для карты beta на базе 0.24. Этот файл описывает подсистемы; окончательная приёмка устройства находится в общей матрице карты.

## F6

`BacktrackRoute` копирует координаты в неизменяемые сегменты обратного пути. Новые точки продолжающейся записи не изменяют snapshot. Паузы, отсутствующие и непригодные координаты разделяют геометрию; расстояние между сегментами не входит в известную длину. Исходный трек и GPX не изменяются.

`BacktrackProgress` использует выбранный сегмент, ребро, долю и последовательную дистанцию. Начальная проекция предлагает неоднозначные участки; последующие fixes проверяют ограниченное окно, а не весь маршрут. Плохой/старый GPS не продвигает маршрут. Отклонение требует трёх пригодных fixes, возврат к линии — двух близких. Прибытие требует последовательного прогресса и двух fixes с точностью до 25 м рядом с концом. Перед разрывом ведение приостанавливается; продолжение требует действия пользователя и позиции у начала следующего сегмента. Через разрыв не рисуется новая дорога, ETA не вычисляется.

`BacktrackMapController` выполняет подготовку и проекции на отдельном worker, сохраняет маршрут до сообщения о начале и владеет только ведением. Запись трека и Flic остаются независимыми. Панель ограничена половиной доступной карты и прокручивается при увеличении текста. Подсказки озвучиваются через существующий голосовой контроллер, редко и только в допустимом жизненном цикле экрана. Пауза GPS, разрыв и прибытие не выдают устаревший курс.

`BacktrackStore` последовательно записывает immutable snapshot отдельно от небольшого состояния прогресса; повторная обработка GPS не сериализует 50 000 координат. При загрузке identity snapshot проверяется. Продвижение после восстановления ждёт новой свежей позиции. Ошибки durable write отображаются пользователю.

`MapTilerMapView.setBacktrackRoute()` и `showBacktrackRoute()` подготавливают геометрию/границы вне UI, отбрасывая устаревшие результаты. При ошибке загрузки стиля применяется локальный нейтральный стиль без сетевых источников. Линии, маркеры и GPS остаются доступны. На нейтральной подложке нет картографических подписей и сетевых glyphs; сохранённое предпочтение стиля не меняется. Повторная загрузка подложки — явное действие.

## F7

`PlaceSearchPanel`: My points / Places, переключение между действующими фильтрами и всеми личными точками, явный Search this map area. Локальный поиск выполняется вне UI по названию, типу и заметке; результаты показываются страницами по 50 с полным счётчиком. Геопоиск не получает личные заметки или точную позицию GPS; optional proximity — центр просматриваемой карты. Выбор результата создаёт только временный маркер. Сохранение и навигация требуют отдельных действий; для площади/водоёма предлагается выбрать точку назначения на карте.

`MapTilerGeocoding` использует native HTTPS GET, до 10 результатов, Unicode encoding, проверяет координаты GeoJSON `[longitude, latitude]`, bounds, тип и атрибуцию. `PlaceSearchController` обеспечивает минимум два символа, debounce 300 мс, отмену, generation guard и общий timeout 10 секунд. Ошибки offline/timeout/403/429/malformed различаются; Retry-After ограничивает повторные обращения. Уход со страницы отменяет доставку callbacks.

Параметры: `MAPTILER_API_KEY` и optional `GEOCODING_URL` в существующей локальной build-конфигурации. Default endpoint: `https://api.maptiler.com/geocoding/`. Значения ключей не записываются в логи/документы. Ответы провайдера не сохраняются на диск. Личная история содержит пользовательские поисковые запросы; её можно очистить.

Контракт сверён с [официальным API](https://docs.maptiler.com/cloud/api/geocoding/). [Условия MapTiler](https://www.maptiler.com/terms/cloud/) допускают временный личный cache, но здесь используется только текущий ответ в памяти. Приложение обращается напрямую, без нового proxy или изменения тарифа. Права аккаунта на распространение и его квота отдельно не проверены.

## Фактические проверки

`scripts/Test-MapGuidanceSearch.ps1`: **45 проверок backtrack + 37 поиска проходят**. Fixtures детерминированы: время/сеть/очередь доставки, паузы, петля, параллельные участки, старт посередине, поздние ответы, Unicode, пустые/сломанные ответы, 403/429, timeout, restart из записанного файла, независимость snapshot и suppression bearing без GPS.

Один реальный HTTPS-запрос с настроенным ключом, строкой на кириллице и без GPS дал **HTTP 200, FeatureCollection, 9 пригодных результатов, атрибуция присутствует**. Запрос выполнен отдельной проверкой HTTP-контракта; это не утверждение о проверке UI телефона. Ответ и ключ на диск не записывались.

Полевая проверка реального движения, airplane mode на телефоне, межпроцессное Android-восстановление, озвучка и проверка 200% шрифта: **NOT RUN в рамках этих подсистемных тестов**. Общая сборка и device QA выполняются при интеграции; успешные JVM fixtures не заменяют их.
